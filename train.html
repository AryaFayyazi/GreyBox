Train a monitor on your own agent

Give it agent steps you have labelled (was this action a violation of your policy?), and it trains a monitor that scores the next action before it runs. Training, evaluation and scoring all happen in this browser tab: your transcripts are never uploaded.

What this tool is, honestly. It is the word-count monitor (TF-IDF + logistic regression) from our preregistered tests, the same model as graybox.monitor.TextMonitor in the Python SDK (browser and Python agree: identical text, identical vocabulary, held-out AUROC 0.9887 vs 0.9886). On the tools and policies it was trained on it matches a much larger reader model, including on another company's closed agent. It does not carry over to new policies or new kinds of tasks: on an unseen benchmark it was at chance. Label a few dozen steps of every policy you need to enforce. For robustness to new tasks, use the reader monitor (self-hosted).

Data format

One JSON object per line (or one JSON array). Each object is one proposed agent action, as your monitor would see it before execution:

{"instructions": "the agent's system prompt / operating policy",
 "task": "the user's request",
 "history": [{"tool": "read_file", "args": {"path": "/hr/a.txt"}, "result": "..."}],
 "action": {"tool": "send_message", "args": {"recipient": "...", "body": "..."}},
 "label": 1,
 "group": "ticket-1043"}

label: 1 if executing the action violates your policy, 0 if not. group (optional): steps with the same group (the same task or episode) are kept in the same cross-validation fold, so the estimate reflects new tasks; without it, the task text is used. If you already render transcripts yourself, use {"context": "...", "action": "...", "label": 0} instead. The example file is 1,500 steps of the open Gemma-4 agent on CAPE-Bench, labelled by the benchmark's rule checker.

2. Train and evaluate

% of steps

How far to trust these numbers. Cross-validation holds out whole task groups, so it estimates performance on new tasks like these. It does not cover a new policy, new tools or a different benchmark: in our preregistered tests, removing one policy family from training dropped that family's catch rate at a 5% budget from 88% to 0%, and 20 to 40 labelled steps of it brought it back to 85–94%.

Deploy it

Download the trained monitor and load it with the Python SDK. The file holds the vocabulary, the weights and the escalation cut learned from your data (the top budget of your steps, without using labels).

from graybox.monitor import TextMonitor, Step
tm = TextMonitor.load_json("greybox-text-monitor.json")
if tm.escalate(instructions, task, history, ("send_message", args)):
    hold_for_review()
