Let the agent police itself

Before a tool call runs, ask the agent itself, in a side conversation that its real conversation never sees, whether the call follows its policy. If it says no, hold the call for a human. You need only the agent's own API: no second model, no training, no GPU, no server. This page does it in your browser.

When it works, and when it cannot. It works when the agent can judge its own policy. Asked about its own proposed calls (flag = most answers say "no"), Gemma-4 flags 97% of its violations, Muse-Glimmer-30B 87%, Qwen3.8-27B 47%, gpt-oss-20b 37%. Claude Haiku 5.5 flags only 5% with a plain question but recognizes its rule misreadings when asked to check each rule in turn. It cannot catch a violation that depends on a fact the agent has not looked at yet (for example how many people are on a mailing list): no judge of the conversation can. For those, check the world before the action runs. Check how well your agent judges its policy on some labelled calls first (section 1).

1. Audit a call with your agent's own API

Calling a model on your own machine (vLLM, Ollama)? Browsers do not let this https page call http://localhost. Use the single-file copy of this tool (open it from your disk), or the Python package (pip install greybox-monitor, graybox.selfaudit).

Its observable state, live

A closed API never returns hidden states, and no outside method can recover their coordinates (paper, Proposition 1). What it can read is the agent's observable state: its answers to a fixed set of 8 yes/no questions about this call (does it comply; one question per rule), each asked in its own side conversation. Each answer moves the point; the coordinates are exact (θ = 2·arcsin√P(yes)), and their distances are the Fisher–Rao geometry of the answers.

Your key is used only for calls from this tab to the provider you chose, and is not stored unless you tick the box. Anthropic calls use the header for direct browser access. The prompts are the ones used in our preregistered tests, verbatim (graybox.selfaudit in Python). "Check each rule in turn" also checks the user's task constraints and takes about ten seconds per answer; "plain" takes about a second.

2. Run an agent and watch it police itself, live

Your model (set in section 1) runs as an agent on a benchmark scenario, in an environment inside this page that gives the same tool results and the same ground-truth labels as the benchmark's own checker (checked on 520 recorded calls). Before each proposed tool call runs, the agent is asked about it in side conversations: its verdict decides whether the call is held, and its answers to 8 questions place the step on the map, so you see where it is heading. A flagged call raises a warning before it runs. We do not claim to predict violations further ahead: our tests found that signal weak.

The agent, step by step
Its observable state: the path of its proposed calls

Each step: one agent call, then (in parallel) the audit's answers and 16 one-word answers for the map, so one step takes about one round trip, a few seconds. With Claude Haiku 5.5 a whole session costs about two cents. The benchmark's checker is shown only to let you judge the audit; a real deployment has no such oracle.

4. Predict the effect before you deploy

For a gate that holds a call when the agent's own audit flags it, the share of violations prevented is about Σk wk τk: for each kind of violation k, its share wk of your agent's violations times the share τk of such calls that the audit flags. Measure τk by auditing some of your agent's known violations (section 1).
