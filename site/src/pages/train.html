Train a monitor on your own agent

Give the trainer agent steps that you labelled: did this action break your policy? It trains a monitor that scores the next action before the action runs. Training, evaluation and scoring all occur in this browser tab. The page does not upload your transcripts.

What this tool is. It is the word-count monitor (TF-IDF and logistic regression) from our preregistered tests. It is the same model as graybox.monitor.TextMonitor in the Python SDK: the browser and Python give identical text, an identical vocabulary and the same held-out AUROC (0.9887 vs 0.9886).
  • On the tools and policies of its training data, it is equal to a much larger reader model, also on a closed agent from another company.
  • It does not transfer to new policies or new types of task. On a benchmark that it did not see, it was at chance.
  • Label a few dozen steps of each policy that you must enforce. For robustness to new tasks, use the reader monitor (self-hosted).

Data format

One JSON object per line (or one JSON array). Each object is one proposed agent action, as your monitor would see it before execution:

{"instructions": "the agent's system prompt / operating policy",
 "task": "the user's request",
 "history": [{"tool": "read_file", "args": {"path": "/hr/a.txt"}, "result": "..."}],
 "action": {"tool": "send_message", "args": {"recipient": "...", "body": "..."}},
 "label": 1,
 "group": "ticket-1043"}

label: 1 if executing the action violates your policy, 0 if not. group (optional): steps with the same group (the same task or episode) are kept in the same cross-validation fold, so the estimate reflects new tasks; without it, the task text is used. If you already render transcripts yourself, use {"context": "...", "action": "...", "label": 0} instead. The example file is 1,500 steps of the open Gemma-4 agent on CAPE-Bench, labelled by the benchmark's rule checker.

2. Train and evaluate

% of steps

How far to trust these numbers. Cross-validation holds out whole task groups. Thus it estimates the performance on new tasks of the same type. It does not cover a new policy, new tools or a different benchmark. In our tests, we removed one policy family from the training data. The catch rate for that family at a 5% budget fell from 88% to 0%. With 20 to 40 labelled steps of that policy, it came back to 85–94%.

Deploy it

Download the trained monitor and load it with the Python SDK. The file holds the vocabulary, the weights and the escalation cut learned from your data (the top budget of your steps, without using labels).
